# Pack setup: situations, saving, handoff, refresh

## Thin or missing data

- Fewer than 5 closed deals: skip the win and loss comparison and write "too little history" in market-physics. If no deal was won, examine the two open deals furthest along and state this.
- No buyer emails written by the user: create no voice file. Say in one line how to add samples: paste two or three recent buyer emails and say "Refresh my pack".
- Fewer than 10 sent buyer emails: shape the voice from whatever exists and flag it as a preliminary read; say in one line that pasted emails and "Refresh my pack" will firm it up. This is a statement, not a question.
- No CRM: calls and email still give voice, pitch, objections, competitors, and a rough motion; amounts and timing often appear in pricing emails and proposals. Decide rep or leader from title and calendar. Mark process lines that are guesses. Open the questions with a short block saying stages and numbers are estimated and that a CSV improves them (open and closed deals with owner, stage, amount, close date, won or lost; when it arrives, redo the CRM and best-deal reading). Put the connection tip inside the summary.
- Nothing connected: skip the summary. Send one short questionnaire instead: sell, lead, or both; what is sold and to whom; average amount and cycle; where leads come from; stage names; how deals are qualified; top competitors; why the named deal went well; two or three recent buyer emails pasted in. Build the voice from the pasted emails.
- Source fails mid-read: retry once, continue, mark totals partial, and report it as an absence in the summary.

## Team files already in the project

Check the owner of each team file. If another person owns it, it came from their leader: read it, do not regenerate it. If the user owns it, this is a refresh, so rebuild it. If a rep brings in a leader's team files, instruct them first to remove any earlier personal versions of buyers-and-competition and deal-lifecycle, since the leader's files supersede them. After that, narrow the scan to the rep's personal deals, calls and email for building voice and working-style, and limit the summary to how the rep writes and the rep's deals. A rep habit that differs from the team process goes into working-style only.

## Saving the files

In Claude, make the files downloadable and explain a project (a workspace where conversations share files). Write the steps for someone who has never made one: create the project, add the files, start new chats inside it. If already inside a project, skip creation; on a refresh, replace the old files. If downloads cannot be made, give one copy block per file under the file name as a heading and tell the person to add each as pasted text content.

Outside Claude, give the copy blocks and say to save them wherever the tool keeps standing instructions or attachments. Do not mention Claude settings or projects.

For a leader or both, after saving, the same closing message that explains the hand-off offers the team pack bundle: the six team files (deal-lifecycle, buyers-and-competition, market-physics, winning-plays, team-standards, scoring-axes, plus crm-guide when the team has one) plus `config/TEAM-ROLLOUT.md`, as one folder named team-pack. Make a zip if the environment can; otherwise list the files to copy. Add a ready-to-paste message for reps, three to five lines, shaped like this with the real versions filled in:

"Here is our team pack folder. Put the files in the same place as your own pack files and do not edit them. Then say "Set up my pack"; it builds only your voice and working style. Current versions: <file> <version>, one per file. Questions or fixes go to me with the file name and the reason."

The rep adds the files to their own space and runs setup, which detects the team files. This is part of the hand-off explanation, so the open question limits stay as they are.

## Founder handoff

When the person says they are handing sales to a first AE or preparing a new hire, run the usual flow and also produce one extra document from the same data: winning-plays and deal-lifecycle combined, ordered the way a new AE should read them. It follows the same hygiene rules and is not another pack file.

## Refreshing

On "Refresh my pack", read again, show a few lines on what changed, and replace only the files that changed. Keep versions and changelog lines per `config/SCHEMA.md`.
